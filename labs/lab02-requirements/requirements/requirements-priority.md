# MoSCoW优先级与当前版本范围

本版依据369份经原填写者确认修订的问卷、课程范围及业务完整性确定优先级。问卷反映使用问题与偏好；具体审核权限及状态边界属于项目设计约束，校方相关制度尚待核实。Must、Should和Could用于确定实施顺序，功能完成情况见开发分支及需求追踪矩阵。

| 级别 | 需求ID与能力 | 依据 |
|---|---|---|
| Must | FR-001～FR-014、FR-016、FR-018～FR-020、FR-032；NFR-001、003～007、009、011～014 | 报名入口与信息填写、状态反馈、任务责任期限、关键通知和隐私等有问卷依据；审核、唯一性、权限和恢复要求来自项目范围、模板与完整性约束 |
| Should | FR-015、FR-017、FR-021～FR-026、FR-033～FR-034；NFR-002、008、010 | 候补163/369（44.2%）；签到记录不清楚93/190；资源接触者审批进度157/243。场地功能提高关注度，仍按课程依赖和工作量安排 |
| Could | FR-027～FR-031 | 物资、推荐、举报、导出和审计界面按业务依赖及复杂度安排在基本功能之后；问卷将场地与物资合并询问，未提供物资单项支持率 |
| 本期不纳入 | 即时聊天、在线文档、视频会议、邮箱、支付、复杂AI推荐、社交媒体系统 | 超出课程活动管理边界；开放题中的提及不自动构成开发承诺 |

Q04中相符37.6%、不相符39.9%（分母343），样本对信息分散感未形成多数共识。Q10有64人无需提醒，通知应提供类型选择。资源申请未接触者为126/369（34.1%），243名接触者的反馈用于分析资源需求，其优先级还取决于实施依赖和课程工作量。NFR-002等验收参数须在相应测试前确定。
