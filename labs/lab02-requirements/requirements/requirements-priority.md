# MoSCoW 优先级与当前版本范围

所有调研证据均为课程实验模拟数据。Must 是拟议最小闭环，Should/Could 是后续可选范围，尚未承诺全部开发。以报名确认、审核、安全和筹备任务的模拟痛点为主要取舍依据。

| 级别 | 需求 ID 与能力 | 依据 |
|---|---|---|
| Must | FR-001～FR-014、FR-016、FR-018～FR-020、FR-032；NFR-001、003～007、009、011～012 | 基础身份/角色、社团与入社、活动创建审核发布、浏览报名取消签到、筹备任务和关键通知构成可追踪闭环；Q02/Q04/Q07、三类访谈及完整性约束支持 |
| Should | FR-015、FR-017、FR-021～FR-026；NFR-002、008、010 | 候补仅 11/20 选择，个人记录和待办有需求但优先于场地、评价与统计的必要性仍需真实调研复核 |
| Could | FR-027～FR-031 | 物资接触者少；推荐、举报、导出及可视化审计属于扩展 |
| Won't for current release | 即时聊天、在线文档、视频会议、邮箱、支付、复杂 AI 推荐、社交媒体系统 | 超出校园活动管理边界与课程规模，模拟开放题亦反对扩大办公功能 |

Should 中 FR-024 场地申请涉及管理员约束，但因 Q13 有 12/20 未接触资源申请，暂不升为 Must。NFR-002 性能阈值须在约定环境下冻结。完整逐项描述见功能/非功能需求文件。
