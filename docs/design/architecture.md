# 核心版本软件设计

设计日期：2026-10-13。需求依据为 requirements-v1.1。本文说明课程演示版本的系统结构、业务规则、权限控制和需求对应关系。

## 技术与结构

使用 Python 3.12 及以上、Flask 3.1、Python 内置 SQLite 和原生 HTML/CSS/JavaScript。单个本地 Web 服务同时提供界面和 JSON 接口，减少个人课程项目的部署依赖；业务代码按应用初始化、数据库、安全、业务接口拆分。默认仅监听 127.0.0.1。

Flask 工厂接收配置，数据库路径和业务时钟可替换，便于用独立临时数据库测试时间边界及并发。SQLite 适合本地课程演示；多实例及高并发部署需要重新评估数据库与服务部署方案。运行数据库、会话和备份不提交到仓库。

## 数据与业务边界

用户的学生或管理中心身份属于平台角色；成员和负责人身份由具体社团的有效成员关系决定。备案申请独立于正式社团存在，申请通过后才能建立社团及负责人关系。成员失效或负责人变更后，服务端每次请求重新核对关系，使权限立即生效。

活动保留需求阶段的状态名称。只有已发布的活动参与时间推进，草稿和驳回活动不会因时间到达变成进行中。Published 允许浏览，RegistrationOpen 才能报名；截止、开始和结束时刻均按大于等于边界推进。取消状态终止后续自动推进。

报名以正式、候补、取消状态表达。并发报名在 SQLite `BEGIN IMMEDIATE` 写事务中检查名额并写入；唯一约束防止同用户同活动重复有效记录。取消、释放名额、首位有效候补转正和通知在同一事务中完成，失败则整体回滚。报名截止时刻禁止报名和自动转正。

筹备任务绑定活动、有效社团成员和期限。只有任务承担人或所属负责人能够更新状态；停用社团不能继续社团业务写操作。个人记录和站内通知仅本人可见；成员名单按业务职责授权，公开页面不含名单、联系方式或内部任务。

## 安全与运行

- 密码采用 Werkzeug scrypt 单向哈希，不保存明文密码。
- 随机会话令牌放入 HttpOnly、SameSite cookie，服务端保留摘要及有效期；退出登录撤销会话。默认会话有效期 8 小时。
- 所有状态变更，包括登录，检查 CSRF 令牌；生产 HTTPS 部署再启用 Secure cookie。
- 服务端限制文本长度、容量、合法枚举和时间顺序；SQL 使用参数绑定；界面转义业务文本。
- 审核、活动状态及成员身份变更留下操作者、对象、结果和时间；日志不记录密码、cookie 或 CSRF 令牌。
- 日期输入统一为带时区 ISO 8601，数据库存 UTC，界面显示本机时间。
- 生命周期可在业务请求中刷新，也可通过定时执行 tick 命令刷新；失败写入运行日志。
- 使用 SQLite backup API 生成一致性备份，恢复到独立目标并校验完整性。演示环境建议每次演示前备份，保留最近 7 个备份；备份不含真实校园个人数据。

输入长度约定：用户名不超过 64 字符；名称和标题不超过 120 字符；主题和地点不超过 120 字符；描述、申请说明和驳回原因不超过 2000 字符；容量为 1～10000 的整数。具体服务端约束以接口校验和测试结果为准。

## 界面规范

公开页面提供活动浏览、社团信息、筛选和日历；登录后的页面按角色提供参与记录、筹备任务、资源申请、审核和统计等功能。页面操作入口与服务端权限保持一致，提交、审核、报名和取消操作均提供结果反馈。

活动状态同时使用文字和配色表示，避免仅凭颜色传达结果。列表支持无数据和加载失败提示，表单保留字段说明及错误反馈。日期按本地时区显示。统计图和明细使用相同的已结束和已归档活动报名、签到与评价数据。字体资源在本地提供，页面适配桌面和手机；启用减少动态效果时，装饰性动画减少或停用。

## 需求与实现对应

| 设计单元 | 关联需求 | 验证重点 |
|---|---|---|
| D-IDENTITY 身份与授权 | FR-001～FR-002；NFR-004～NFR-006、NFR-012；BR-009 | 错误登录、退出与过期、CSRF、跨社团越权 |
| D-CLUB 社团与成员治理 | FR-003～FR-005、FR-032～FR-034 | 重复入社、成员变更、申请主体、审核通过才建立负责人关系 |
| D-ACTIVITY 活动与审核 | FR-006～FR-011；BR-006～BR-007、BR-011 | 隐藏草稿、审核职责、发布时间及状态边界 |
| D-REGISTRATION 报名与签到 | FR-012～FR-017；NFR-003、NFR-011；BR-001～BR-005、BR-010 | 并发容量、重复提交、取消转正、截止边界、签到权限 |
| D-COLLABORATION 筹备与通知 | FR-018～FR-020；BR-008 | 有效成员分配、任务归属、原子通知及幂等读取 |
| D-OPERATIONS 审计与恢复 | FR-031；NFR-007、NFR-013～NFR-014 | 审计留痕、日志隐私、独立备份恢复 |
| D-RESOURCE 场地与物资 | FR-024、FR-027；BR-012 | 申请与审批职责分离、同场地半开时段冲突、并发审核、物资归属 |
| D-FEEDBACK 反馈与统计 | FR-025～FR-026、FR-028～FR-030 | 已签到才评价、计数与记录一致、推荐规则可解释、举报隐私、导出不含个人资料 |

待办、活动日历、资源申请、反馈和统计共用上述权限和业务数据。场地审批使用半开时间区间，结束恰好等于下一次申请开始不构成冲突；两个同时审批请求仍在同一写锁机制下检查。物资功能记录需求与准备状态。活动评价限已签到且活动结束的学生；统计直接聚合已结束活动的正式报名、签到和评价记录。

规则推荐依据学生本次选择的主题匹配度，其次按开始时间和活动 ID 排序，界面展示排序依据，不接入外部模型。举报记录仅本人和管理中心可见。CSV 只包含活动汇总，并对可能被电子表格解释成公式的标题进行转义。
