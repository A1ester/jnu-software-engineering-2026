# 迭代计划

迭代用于控制个人课程项目范围。Iteration 0 已完成需求与项目基础整理，其余迭代尚未执行，均标为 PLANNED。每次开始前应重新核对前置依赖和可用课程时间。

## Iteration 0：需求与项目基础（DONE）

- **目标**：按教师模板形成可独立评审的 requirements-v1.1，并建立轻量项目管理基础。
- **Backlog**：PB-012。
- **主要交付物**：修订 SRS、四个需求模型、需求追踪、CR-001、CR-002、项目计划、Backlog、迭代计划、风险登记。
- **完成判据**：章节覆盖模板；FR/NFR/BR 连续且口径一致；调研材料真实性说明保留；变更记录已纳入 requirements-v1.1；未进入业务代码开发。

## Iteration 1：用户、权限与社团治理基础（PLANNED）

- **目标**：建立身份、授权、社团备案治理和社团成员关系的最小可运行增量。
- **Backlog**：PB-001、PB-002、PB-014、PB-020、PB-021；Should 项按评审与时间选取。
- **主要交付物**：身份与权限、社团备案、状态与负责人关系、入社和成员管理的设计、实现、测试记录及更新后的追踪矩阵。
- **完成判据**：普通学生只能管理自己的申请；社团负责人只能管理自己负责的社团；管理中心工作人员按职责执行跨社团治理；纳入范围的需求满足验收条件。

## Iteration 2：活动、审核与报名（PLANNED）

- **目标**：完成活动从草稿到报名关闭的核心闭环。
- **Backlog**：PB-003、PB-004、PB-005、PB-015；范围优先覆盖 Must，Should 视进度纳入。
- **主要交付物**：活动、审核、浏览、报名、取消和容量控制增量及测试记录。
- **完成判据**：活动提交与管理中心审核职责分离；生命周期符合 BR-001～BR-007、BR-011；并发报名不超容量；截止时间后的报名和取消按规则拒绝。

## Iteration 3：签到、通知与筹备协作（PLANNED）

- **目标**：支持活动执行阶段的签到、关键通知和任务协作。
- **Backlog**：PB-006、PB-007、PB-008、PB-016、PB-017；Should 项按时间选取。
- **主要交付物**：签到、任务、站内通知增量和相关测试记录。
- **完成判据**：Must 功能满足验收条件；签到和任务受资源归属控制；关键事件通知不重复。

## Iteration 4：扩展功能（PLANNED）

- **目标**：在核心闭环稳定后选取高价值 Should/Could，避免扩展功能挤压 Must。
- **Backlog**：PB-009、PB-010、PB-011、PB-018、PB-019。
- **主要交付物**：经评审选定的资源、反馈、统计或治理增量。
- **完成判据**：只实现已明确纳入的条目；每项通过关联验收；未完成条目保持 PLANNED，不以占位实现代替。

## Iteration 5：测试、修复与发布（PLANNED）

- **目标**：验证已实现范围，修复阻断问题并准备课程发布。
- **Backlog**：PB-013。
- **主要交付物**：测试报告、缺陷记录、发布清单、用户说明和最终追踪矩阵。
- **完成判据**：已实现 Must 主流程通过约定测试；高影响缺陷已关闭或有明确处置；发布内容与文档一致且无敏感信息。
